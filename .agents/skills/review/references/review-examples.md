# 리뷰 결과 사례

사례는 결과를 구체적으로 쓰기 위한 안내이며 새로운 팀 규칙이 아니다. 실제 확인 항목은 저장소 PR 템플릿을 사용한다.

## 검증 범위 구분

“도우미의 정상·실패 경로와 파일 비변경을 임시 저장소에서 확인했습니다. 에이전트의 자동 선택은 미검증입니다.”처럼 확인한 동작과 확인하지 않은 동작을 구분한다.

## 문제를 발견한 경우

대상 파일·위치, 발생 조건, 실제 영향과 확인 근거를 함께 설명한다. 예: “검사 실패 뒤 수정 명령까지 이어져 검사 요청만으로 파일이 바뀝니다. 검사와 수정 경로를 분리할 필요가 있습니다.”

## 문서·구조 검토

작성 규칙과 실제 구현이 다르면 두 상태를 구분해서 적는다. 구조 규칙이 있다는 이유만으로 미구현 기능을 완료로 표시하거나 기존 파일을 일괄 이동하지 않는다.

## 절차 확인

Code Rabbit 리뷰 여부와 실제 팀원 Approve 수를 확인한 사실로만 보고한다. 필요한 승인이 부족하면 부족하다고 알리며, 검사·설명 요청을 승인이나 merge 권한으로 확대하지 않는다.
