# PR 설명 작성·검토·게시

제목은 `종류/#이슈번호: 작업한 내용`으로 작성한다. 예: `feat/#1: MainView 개발`.

- 규칙 설명 요청: 제목 형식을 설명하고 본문 구성은 실제 `.github/PULL_REQUEST_TEMPLATE.md`에서 확인한다.
- 초안 작성·검토 요청: diff와 실제 템플릿을 읽고 변경 이유·작업 내용·검증·리뷰할 부분을 작성한다. 상황별 표현이 필요하면 [작성 사례](references/writing-examples.md)를 읽는다. 초안만 작성한다.
- 게시·갱신 요청: 명시된 저장소·PR의 base/head와 상태를 확인하고 요청된 설명만 게시·수정한다. 리뷰 요청·Ready 전환·merge를 함께 실행하지 않는다.

템플릿을 별도 복제하지 않는다. UI 변경 시 화면 첨부, 해당하지 않을 때 화면 항목 삭제는 실제 템플릿 안내를 따른다. 확인하지 않은 검증은 완료로 표시하지 않는다.
