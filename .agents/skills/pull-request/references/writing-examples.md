# PR 작성 사례

아래는 표현을 돕는 예시이며 새 필수 항목이나 검증 의무가 아니다. 실제 본문 항목은 저장소 템플릿을 사용한다.

## 문서만 변경한 경우

- 개요 예: “작업별 규칙과 검사 경로를 나눠 필요한 안내를 쉽게 찾도록 정리했습니다.”
- 작업 내용은 실제로 바꾼 Skill·참고 자료·도우미로 한정한다.
- 검증 예: “형식 검사와 내부 참조 확인을 통과했습니다. 새 세션의 자동 선택은 확인하지 못했습니다.”
- 화면 변경이 없다면 템플릿 안내에 따라 구현 화면 항목을 삭제한다.

## UI를 변경한 경우

- 실제 적용 대상과 동작을 설명하고 해당 iPhone·Apple Watch 화면을 첨부한다.
- 실행하지 않은 기기·상태는 미확인으로 구분한다. 두 플랫폼 모두 확인한 것처럼 쓰지 않는다.

## 검사 일부를 실행하지 못한 경우

“SwiftLint가 설치되어 있지 않아 lint는 실행하지 못했습니다. git diff --check는 통과했습니다.”처럼 실행 결과와 미실행 이유를 분리한다. 검사를 실행하지 못한 항목에 완료 표시를 하지 않는다.
