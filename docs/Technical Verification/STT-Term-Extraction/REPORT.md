# 연구 과정과 검증 결과

기록 기준: 2026-10-22. 대화 전사본이 아니라 저장된 증거에 근거한 연구 요약이다. 원문·자동 라벨·사람 정답·모델 출력·실기기 관측을 구분한다.

## 목적과 자료

목적은 처음 보는 실험 문서에서 발화할 법한 전문용어를 골라 STT 힌트 후보로 제공하는 것이다. 모델 입력은 앱이 파싱한 text이며 일반 iPhone까지 지원하는 방향이다. 실제 음성 개선은 아직 측정하지 않았다.

자료 수는 시점과 모집단이 다른 스냅샷이다. 추출 성공이나 품질 통과가 학습·재배포 허가를 의미하지 않는다. 자동 검수 결과를 사람 정답으로 표시하지 않았다.

| 단계 | 당시 수량과 범위 |
|---|---|
| 10/15 수집 | 등록 1,722, 프로토콜 후보 1,017, 원본 확인 1,661, text 추출 성공 1,648 |
| 권한 확인 | 482건, 사용 가능 부분집합 320건; 상업용 학습에서 비상업 전용 자료 보류 |
| Luna 품질 평가 | 독립 대상 1,529, 유효 평가 1,491, 사람 정답 0 |
| 다양성 후보 | 983문서·979원본 그룹; 한국어 383, 영어 598, 실제 혼용 2 |
| 10/16 v3 학습 | 한국어 412항목·3,200문단, 영어 226문서·1,306문단 |

한국어 412항목의 원본 계열은 10개였고 한국어 학습 문단의 96.2%가 분석화학·환경식품에 집중됐다. 학습량 증가를 분야 일반화로 해석하지 않았다. 한영 문서를 함께 학습하는 것과 실제 혼용 원본도 구별했다.

## 생성·경계·순위 진단

손실은 생성 누락, 허용 필터 탈락, K 예산, 순위 손실로 나누었다. 후보에 없는 용어는 랭커로 복구할 수 없다. 교정·샘플주기·곡선반경 같은 일반 표현의 high는 문맥을 다시 검토했다.

10/21 새 24문서의 구조 보존 projection은 언어 평균 R100 80.97→79.15%였다. R50은 59.93→61.81%였으나 새 회수 6개·추가 누락 9개로 손익이 달라 기본값을 바꾸지 않았다. 앱 파서의 블록·셀 보존과 수집 XML 평탄화 문제를 구분했다.

같은 문서에서도 admitted pool의 중요 용어는 한국어 65/66, 영어 110/111개였고 high 필터 탈락은 0개였다. 이 표본에서는 후보 허용보다 순위가 병목이었다. 부분 LLM 기준에 없는 출력을 오탐으로 세지 않았으므로 precision은 주장하지 않는다.

## 모델 크기와 실기기

8비트 기준은 보존하고 단어 임베딩 LUT만 4비트로 압축했다. 나머지 가중치 blob 275개는 동일하다. 압축에는 평가 문서나 라벨을 사용하지 않았다. 전체 모델 4비트 압축의 과거 실패와 구분한다.

| iPhone 17 native fusion, KO12·EN12, 유효 3쌍 | 8비트 | 임베딩 4비트 |
|---|---:|---:|
| 모델 패키지 | 117.92MB | 69.92MB |
| 앱 peak physical footprint 중앙값 | 197.61MB | 198.82MB |
| 앱 peak resident 중앙값 | 350.77MB | 314.74MB |
| 24문서 처리 중앙값 | 29.52초 | 28.49초 |
| 새 프로세스 초기화 중앙값 | 865ms | 709ms |
| 언어 평균 Recall@100 | 80.97% | 81.81% |
| 언어 평균 Recall@50 | 59.93% | 57.95% |

8/4·4/8·8/4 순서의 144문서 추론은 대응하는 Mac 중요 용어 회수 집합과 같았다. 화면 이탈·백그라운드 실행은 보존하고 집계에서 제외했다. 모든 유효 실행의 시작·끝 발열은 nominal이었다.

footprint는 앱 프로세스의 10ms 샘플값이며 Core ML 서비스 전체나 샘플 사이 피크를 뜻하지 않는다. OS 캐시는 따뜻했을 수 있다. 속도 차이는 쌍마다 +1.59, −0.27, −1.83초여서 일관된 개선으로 해석하지 않는다.

과거 4문서의 약 3,060→112MB 비교는 다른 입력·구성이다. 원인은 512-token 처리와 달리 4,096까지 허용한 Core ML shape 계약 등이었고, 원래 기준에 대한 bit-exact 동등성에는 실패했다. 새 24문서 비용과 직접 섞지 않는다.

## 상위 50개 순위 보정

선정 옵션은 기존 상위 75개 안에서만 정렬한다. 모델 점수에 `0.005 × log1p(min(서로 다른 원문 출현 위치 수, 4))`를 더하고, 완성형 한글을 포함한 정규화 길이 2 이하 후보에는 0.05를 뺀다. 겹침 윈도우가 같은 위치를 반복해도 한 번만 센다. 동점은 기존 순서다.

원문 표면·scalar 위치·반환 모델 점수는 유지하며 상위 100개 용어 집합도 보존한다. 용어·문서 ID별 정답 목록을 피처에 쓰지 않는다. native fusion이 기본이며 보정은 명시적 검증 옵션이다.

| 개발자료 | 한국어 R50 | 영어 R50 | 언어 균등 평균 |
|---|---:|---:|---:|
| 24문서 | 64.40→65.99% | 51.49→56.83% | 57.95→61.41% |
| 별도 기존 61문서 캐시 | 56.23→58.11% | 48.27→48.37% | 52.25→53.24% |

최초 전체 후보 재정렬은 24문서에서 65.52%였지만 별도 61문서 영어가 48.27→43.74%로 하락해 기각했다. 최종 후보도 두 개발자료에서 301개 조건을 비교한 뒤 골랐으므로 독립 holdout이나 확정된 일반화가 아니다. 61문서 영어 개선 0.09pp는 작다.

## 검증과 회귀 수정

- 기존 모델·원문·라벨·잠금 테스트 보존, SwiftLint 규칙·CI 변경 없이 오류·경고 0건.
- Swift XCTest 5건, 압축 Python 테스트 10건, 순위 Python 테스트 3건 통과.
- 토크나이저·scalar/UTF-16·ledger·char 입력 배열과 절 제목 재생은 24/24 동일.
- 순수 후보 생성·정제 448개 비교와 고정 85문서 순위 구현 비교 8,500개 출력 일치.
- 수정 후 실제 4비트 native와 guarded API를 24문서에서 검증; native 용어·위치·순서 24/24 기준 일치.
- 같은 forward의 보정 전후 상위 100개 집합과 공개 guarded API 결과 24/24 일치.
- 실제 UTF-8 SHA·scalar 범위·유한 점수 검증, 재개 시 61개·24개 캐시 재사용 확인.

코드 분리 중 한국어 부분 문자열 후보 호출과 조사 뒤 중복 조건이 달라진 회귀를 발견했다. 원래 동작을 복구하고 테스트를 추가했으며 해당 중간 실행은 최종 근거에서 제외했다. 실제 native 점수는 과거 캐시 대비 최대 0.000324 차이가 있어 Float bit 단위 동일성은 주장하지 않는다.

## 남은 과제

사람이 검수한 중요도·경계 정답, 새로운 원문 계열과 실제 앱 파서 입력 평가가 필요하다. 새 순위 옵션의 iPhone 시간·메모리는 아직 측정하지 않았다. 같은 녹음으로 힌트 없음·모델·사람·방해 힌트를 비교하기 전 실제 STT 개선이나 배포 적합성을 확정하지 않는다.

모델·자산 SHA와 사용 조건은 `Model/MODEL_CARD.md`에 기록한다. 원문과 상세 실행 증거는 연구 작업공간에 보존하고 이 PR에는 복사하지 않는다.

PR 정리에서 사용하지 않는 GB 랭커·재압축 도구·빈 리소스를 제외했다. 한국어·영어 각 12문서 재실행에서 native·guarded 상위 50/100개 용어 집합과 guarded 순서는 모두 유지됐다. native는 1문서에서 두 용어 순서가 바뀌었고 최대 Float 차이는 0.000533이었다. 해당 문서의 동일 모델 경로 대조 재실행에서는 정리 전후 점수까지 일치했지만, 전체 추론의 bit-exact 동등성은 주장하지 않는다.
